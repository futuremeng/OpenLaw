# 界面语言与渐进披露规范（面向非技术用户）

本文件是用户可见文案的成文规范：桌面端面板、弹窗、提示条（toast）、空态与错误说明，
以及 CLI 提示。产品面向律师、法务与普通公众——他们不知道也不需要知道 SQL、命令行参数、
环境变量、目录结构长什么样。术语底线见 AGENTS.md「产品与术语」，本文件是其界面层展开。

## 三条硬规则

1. **目标语言**：说「用户要做的事」，不说「系统内部怎么实现」。按钮以动词 + 用户目标命名
   （查看待复核条目 / 获取最新法规 / 开始获取），不用内部流程名（去复核 / 采集与更新 /
   抓取 / 载入队列 / 落判）。内部标识（JSON 字段、列名、错误码）不受此限。
2. **渐进披露**：默认视图只出现完成目标所需的状态、数字与最多两个动作。技术参数
   （限速毫秒、页数上限、起始页、连续空白页、签名私钥路径、数据包目录）一律进
   「高级设置」折叠，**但护栏下限不得移除也不得藏起来绕过**（govcn ≥2 秒/条、
   govlist ≥2000 毫秒/页）：藏在高级里仍要带「不少于 2 秒」这类说明。
3. **诚实展示**：缺失、失败、未验证如实说明，并紧接一句「下一步怎么做」。
   禁止占位内容、禁止把失败渲染成中性数字（见下方「成功 0 · 失败 N」条）。

## 主视图禁止出现

以下内容只能出现在「高级设置 / 技术细节」折叠内，且必须同时给出白话解释：

- SQL / LIKE 通配符（`gov.cn%`、`flk%`）——来源一律用真实来源名下拉，不用模式串；
- 命令行参数名（`-data`、`-endpoint`）与环境变量名（`OPENLAW_BROWSEROS_ENDPOINT`）；
- URL、端口、回环地址（`http://127.0.0.1:9211/mcp`）；
- ISO 8601 UTC 时间戳（`2026-10-28T02:28:32Z`）——界面一律显示本机时间
  `YYYY-MM-DD HH:mm`，原始 UTC 串留在 `title` 属性里供核对，不做美化；
- 数据库 / schema 版本号、数据目录路径、「来源：命令行 -data」这类运维说明；
- 内部错误码（OL-100x）、堆栈、参数回显串。

## 产品自称

窗口标题、macOS Dock/Finder 显示名（`CFBundleDisplayName`）、关于框与启动日志里的
产品自称一律用 **开源法律法规数据库**（侧栏短名「法律法规库」）。内部旧称
（「语料台」一类开发期绰号）不得出现在任何用户可见位置，也不得作为文档标题；
`desktop/title_test.go` 断言窗口标题与打包显示名一致且不含该旧称。
数据层内部术语「语料」只允许出现在代码、文档与数据文件名里，不得进入 UI 与 CLI 提示
（对应说法：语料 → 法规库 / 法规库数据；语料包 → 数据包）。

## 三个页面的信息层级

- **库总览**：数字 → 处境（一句话说明这批数据现在能不能用）→ 下一步动作（最多两个按钮）。
  技术信息（路径、格式版本、来源说明）折叠在页尾。「法规库分法域与构成」是单区块：
  一个法域一个块（中国/欧盟/美国恒常三块）——块头 = 部数 + 该法域待复核 + 下钻入口
  （点击带法域筛选进浏览页），块体 = 该法域按效力等级构成条；0 部如实「尚未收录」+
  补救指引，有部数无留证原文如实说明，0 条文的法域不得说「均已复核」。三法域块并列
  多列显示，列宽随数据状态：恰好一个法域有构成条时该位置占宽列，
  两个及以上有构成条时自动等宽；窄屏回落单列。「最近获取」「最近复核」归入
  所属法域列（每列 = 计数→构成→动态的完整档案；空列如实「暂无」）；
  「各等级的精确数字」折叠明细同样归入本法域列，与占比条同批数据就地可对账。
- **智能审核**（取代原「人工复核」，见 docs/design-agent-review.md）：统计（智能体确认 /
  人工确认 / 需要您纠正 / 尚未审核 三口径分列）→ 通道状态与「开始智能审核」→
  例外队列（点选进右列详情，看原文与没把握的原因）→ 一键纠正（结论依据必填，
  确认/驳回）。人工不再逐条署名落判——署名固定「本机用户（人工纠正）」，
  但结论依据必填、复核记录照写。
- **获取最新法规**（维护工作区）：来源状态（本机有什么、缺什么）→ 进行中的任务 →
  获取表单（官方库逐条获取 / 规章目录）→ 数据自检 → 版本信息。离线更新包不在本面板——
  其唯一落点是独立的「离线更新包」面板（一处写路径，不摆两套按钮）。限速、起始页、
  连续空白页等护栏参数由程序固定，不再作为界面输入（护栏下限不得移除）。
  BrowserOS 未配置时给可照做的中文步骤，端点地址与环境变量收进「技术细节」。
- **初始化法规库**（空库引导）：处境（法规库为空，如实说 0 部）→ 第一步两条路线二选一
  （导入离线更新包 / 从官方渠道获取——只给去处，不重复获取控件）→ 第二步智能审核通道
  状态（未配置给指引，不阻塞）→ 完成后「开始查法规」（库仍为空时禁用，不得装作可查询）。

## 界面结构基线（2026-10-30 重构后）

- **两个工作区，完整互斥切换（2026-10-31 起）**：主导航只谈「查法规」（关键词检索 /
  按条件筛选 / 法规检索）；全部维护功能（库总览 / 智能审核 / 地域标引 / 获取最新法规 /
  离线更新包）收进独立维护工作区——只经左列底部「维护法规库」入口（`#nav-maintain`）
  进入。切换是整套换：进入维护后主导航连同「查法规」组头一起收起、底部入口收起，
  左列只剩维护子导航（`#nav-group-maintain`，首位常驻「返回查法规」出口）；回到查询后
  维护子导航整套收起。左列任何时刻只呈现一套导航，不得两套并排。维护工作区内面包屑根
  改报「维护法规库」。工作区选择持久化（`ol-ws`）。原「公众/专业模式」切换已撤除，不得回流。
- **空库初始化（2026-10-31 起）**：启动时确认库为空（`Status` 可读且法规数为 0）默认落到
  「初始化法规库」面板（诚实展示：读不到状态不算空库）；首页搜索框下给一行空库提示与
  「去初始化法规库」。初始化面板只指路不重复写路径控件，获取与导入控件的唯一落点在
  维护工作区（获取最新法规 / 离线更新包）。
- **每屏一个页头**：每个面板以 `.page-head` 开头（标题 + 一句话处境说明），主行动紧随其后，
  工具条其次。用户先知道「在解决什么问题」，再看到控件。
- **顶栏承载当前位置与本机状态**（`#topbar`）：面包屑给出「法律法规库 › 按条件筛选」，
  浏览页还把当前筛选摘要挂在当前位置后面（`#crumb-ctx`）；右侧常驻本机法规库总数
  （`#t-lib`）、待复核提醒（`#t-pending`，为 0 时收起而不是显示 0）、进行中的获取任务
  （`#t-task`）、当前地区（`#t-region`）与外观／密度图标工具（`#theme-toggle`、`#t-density`）。
  状态必须在任何面板都看得见，不是进某个面板才出现一次。
- **三栏布局（2026-10-30 起）**：左列 = 导航 + 筛选栏（`#side`），中列 = 面板与列表
  （`main`），右列 = 共享详情（`#detail`，默认收起，点选条目展开）。原文、条文核对、
  例外详情都在右列展开；「一键纠正」工具条（`#fix-bar`）只在例外详情下出现。
  窄窗口下右列先收窄、再改浮层覆盖，不得挤没中列列表。
- **左列导航 + 筛选**：导航项挂计数徽标——`#cnt-review`（需要您纠正）、`#cnt-region`
  （机器建议待复核），获取任务运行时点亮 `#dot-collect`。计数读不到时清空徽标而不是
  留旧值；徽标用紧凑写法（3.6 万），精确条数挂在 `title` 里供核对。筛选栏（`#filters`）
  仅「按条件筛选」展开。左列不得出现状态与外观工具（法规库总数、待复核提醒、
  主题/密度）——同一信息不在两处各写一套。
- **确认来源如实分列**：已确认条目按来源分三种徽章——「已复核 · 智能体确认」
  （`.badge.agent`）、「已复核 · 人工确认」（`.badge.human`）、「已复核」（历史条目，
  来源未记录，中性 `.badge.ok`）；统计卡同样三口径分列。历史确认不得冒充智能体确认
  或人工确认（诚实展示纪律，见 docs/design-agent-review.md）。
- **图标只承载识别，不承载结论**：导航项、分面组头、面板头、工具按钮用 16px 线性图标
  （`data-icon` 声明，`app.js` 的 `ICON_PATHS` 集中注入，跟随前景色）。结论一律仍是文字与
  数字：图标不得替代状态、计数或缺失说明。
- **面板有面板头**（`.pane` / `.panehd`）：列表列与详情列各有其主（条目 / 命中），
  原文与核对在右列详情展开（法规原文 / 条文与核对 / 需要您纠正的条目）。
  面板头如实报「显示 N / 共 M」——取列有上限时不得让人以为屏上就是
  全部；上限之外的说明挂在 `title` 里。阅读控制（字号 / 行宽）挂在右列详情头。
- **筛选栏常驻左列，是定位法规的主手段**：多维筛选（`.filters` / `.fgrp` / `.fchip`）——
  效力等级、复核状态、来源、公布年代、地区五个维度，
  每个可选值挂**分面计数**。计数按「其余条件已生效、本维度不限」给出（Go 侧
  `BrowseFacets` 与 `BrowseLawList` 共用 `browseWhere`，列表与计数不会两说），
  选中一项后其余维度立即收窄，计数为 0 的选项禁点。当前生效的筛选必须回显成一句白话
  （「当前筛选：类别 行政法规 · 地区 北京市」），不得让用户误以为在看全库。
- **分面组可折叠，且折叠后仍能看出筛的是什么**：每个维度有自己的组头（`.fhd`：chevron +
  微标题 + `已选 X`／`N 项` adornment，`aria-expanded` + `aria-controls`），折叠状态持久化
  （`ol-fgrp`）。长维度（公布年代、来源）默认收起并只列前若干项，其余用「显示全部 N 项」
  展开——筛选栏不得长成一条竖河。窄窗口下右列详情先收窄、再改浮层覆盖，
  **筛选栏始终留在左列，不因窗口变窄而搬进面板或藏起来**。
- **地区是筛选维度，不是全局开关**：地区控件（省/市下拉、按我的位置、应用／不限、试判定与
  说明）只出现在筛选栏的「地区」维度里；状态只在顶栏报一行结果（`#t-region`）。定位与应用
  地区即套用该筛选，「清空筛选」一并取消——不得出现「用户不知道为什么列表变短了」。
- **未标注必须如实，但一行只说一次**：条目行的已知值排一行（等级 · 地域 · 机关 · 施行日期），
  缺失项合并成一个安静标记「未标注 N 项」，具体缺什么与去哪补挂在 `title` 里；不得逐字段
  重复「未标注」（同一行三遍未标注是噪声，不是信息）。按地区筛选时，未标注区划码的条目按
  名称中的地名匹配，其数量由 `#f-region-note` 单独说明；效力等级/来源未记录的条目不参与该
  维度筛选，仍会出现在结果中，这一限制写在筛选栏脚注里。
- **缺失不得占用第一眼**：默认取列把未标注效力等级的条目排在已标注之后
  （Go 侧 `browseOrder`；SQLite 里 NULL 排最前，实测本机语料前 300 条因此全是未标注条目）。
  这是显示规则而非隐藏：缺失仍在行内如实标出，脚注必须声明「排在列表最后（只影响顺序，
  不影响可见性）」，且必须有 Go 层测试守住顺序（`TestBrowseLawListOrdersUnlabeledLast`）。
- **数据既给数字也给形状**：法规构成用堆叠占比条（`.bars` / `.bar`，段长 = 条目数比例，
  按最大等级归一），精确数字收在「各等级的精确数字」折叠；检索结果仍不重排序。
- **视觉克制**：中性色板 + 语义令牌（`--bg/--panel/--ink/--muted/--line/--acc/--ok/--warn/--bad`
  与侧栏令牌 `--side/--side-ink/--side-line/--side-hover/--side-acc`），层级靠字号与间距而不是
  边框堆叠；浅色与深色共用同一套令牌，深色由系统偏好与手动切换（`html[data-theme]`）两条
  路径给出；缺失/未知一律中性灰徽章，不伪装成状态色。
- **显示层偏好不得影响数据口径**：密度（`html[data-density="compact"]`）、原文字号
  （`--read-size`）与行宽（`.narrow`）只改显示，取列条件与分面计数不受其影响（冒烟门禁
  核对「显示偏好不改取列条件」）。
- **反馈就地给出**：inline 提示、任务状态条、空态指引；不用弹窗承载状态。动效只有一次
  极短淡入，并尊重 `prefers-reduced-motion`。

## 门禁

- 文案改动同步本文件与 CHANGELOG.md；阶段进展同步 docs/tasks-opencourt-bridge.md。
- 前端契约测试必须仍绿（`go test ./desktop/`）：新增 `$("#id")` 必须在 index.html 声明；
  `app().Method(...)` 实参个数必须与 `main.App` 方法签名一致——一处不符即整块面板空白。
- 界面结构门禁（`desktop/ui_contract_test.go`）十条：HTML/JS 用到的类名必须在 style.css
  有规则；每个面板必须有页头（`.page-head` 或首页 `.hero`）；技术字样（schema_version、
  环境变量、URL、LIKE 通配符等）不得出现在 `<details>` 之外；样式层必须给出深色令牌
  与前端 `data-theme` 切换；三栏结构必须齐备（左列导航 + 筛选栏、中列面板、右列共享
  详情带一键纠正工具条），智能审核控件（开始审核 / 统计 / 例外队列）必须在位，
  旧人工复核控件（复核人输入框、批量落判、手输路径、构建签名包）与状态/外观工具
  不得回流左列，前端必须同时调用 `BrowseLawList` 与 `BrowseFacets`（列表与计数同源）
  并接上 `AgentStatus`/`StartReviewTask`/`AgentStats`/`ExceptionList`/`CorrectDoc`；
  主区必须先出现顶栏且状态、外观/密度工具都在顶栏（左列不得另起一套）；导航项与面板头
  必须带图标声明且图标由脚本集中注入；五个分面组必须有可折叠组头与计数 adornment 并持久化
  折叠状态；条目行的缺失必须合并成一个标记而不是逐字段重复；独立维护入口（`#nav-maintain`）
  与维护子导航必须在位、「公众/专业模式」控件不得回流；`panel-setup`（初始化）与
  `panel-pack`（离线更新包）必须在位，且更新包控件只允许出现在 `panel-pack` 一处。
- 前端接线冒烟（`desktop/frontend/wiring_smoke.mjs`，由 `TestFrontendWiringSmoke` 调用）必须仍
  打印 `SMOKE_OK`：它桩化 DOM 与 Go 绑定，把 api.js + app.js 真实执行一遍（切面板、检索、
  载入队列、渲染任务、切外观），核对侧栏计数、构成占比条、任务状态、分面计数随筛选变化
  与诚实文案确实产出。本机无 node 时该测试跳过并如实标注，不算通过。
